# Playwright 扩展实测：问题与解决方案

本文件保留修复前的实测事实；后续实施和验收见[修复记录](playwright-repair-acceptance-20260913.md)。

日期：2026-09-13。测试基线：提交 `b2d2d9c`，项目版本 `2.0.0-beta.3.pubmed.1`；macOS、Chrome 官方 Playwright 扩展 `0.4.0`、Playwright CLI `0.1.19`、Node.js `v26.3.1`。本轮未修改业务源码、未发布新版本；仅在实测编排中使用 Playwright 将已绑定的任务标签置于前台。下述代码修改方案尚未实施。

## 本轮已经确认的结果

PubMed 官方接口查询 `31647093[uid] OR 37935836[uid]`，总命中 2 条，完整提取 2 条。检索和元数据本身不经过浏览器，不能据此证明扩展可用。

扩展在绑定普通 PubMed 标签后，通过统一 CLI 的 `doctor --browser` 读到了真实标题和地址。后续知网实测进一步确认：将绑定标签置于前台后，两篇中文文献完成检索、题名作者匹配、自动点击、下载目录检测及归档，均为 3 页正文，首页题名和第一作者核验通过。重跑原命令均返回缓存成功，没有生成重复文件。

其他出版社测试了 DRPress 和 Frontiers 各一篇。两者通过统一 CLI 的公开 HTTP 分支生成文件，命令均返回 `complete`，但文件不完整且无法解析，不计作合格全文。DRPress 在独立目录重取一次，得到同一 SHA-256 的损坏文件；原命令续跑仍将它判为缓存成功。这是本轮最需要优先修复的问题。

**交付统计：4 篇新对照样本中，2 篇知网正文通过核验，2 篇出版社文件不合格。** DRPress 复核副本不另算一篇。知网未捕获到下载事件，成功来自点击后的下载目录备用检测；出版社走直接 HTTP，因此本轮没有证明扩展的下载事件捕获或 PDF 查看器保存已可用。

Oxford 样本为 [Within family Mendelian randomization studies](https://doi.org/10.1093/hmg/ddz204)，PMID `31647093`。本次未得到下载事件或归档文件。用户明确要求跳过人工保存，已记录为“用户跳过”，不是“无权限”或“文献无法获取”。PMID `37935836` 只提取了题录，原计划的 PMC 对照未执行；随后改测知网中文和其他出版社。

## 问题及拟议改法

| 优先级 | 现场事实与影响 | 建议解决方案 | 验收条件 |
|---|---|---|---|
| 最高 | DRPress 和 Frontiers 的 HTTP 响应声明长度大于实际收到的字节数，文件尾部缺失且解析失败；`direct_pdf` 只检查文件标头，仍进入归档并返回成功。SHA-256 只能证明归档复制一致，不能证明原始下载完整。 | 读取同一次响应的状态、长度和编码信息，累计接收字节；拒绝声明长度不符及未请求的部分响应。区分完整性错误、格式错误和正文身份未核验；不完整文件保留为临时诊断产物，不标完成。有界重试后按正常流程进入浏览器来源或明确失败，不能覆盖证据。 | 模拟提前 EOF、分块中断和长度不符，均不能 `complete`；真实下载能解析后再核对题名、作者和正文类型。不能只依赖末尾标记或页数。 |
| 最高 | DRPress 损坏文件已进入检查点，重跑返回 `cached=true`；常规 DOI 下载不会调用 PubMed 分支的正文检查。 | 共享完整性核验应用于首次归档及续跑。旧检查点也重新检查文件有效性，失败返回具体原因并允许受控恢复。将“未安装解析器”“已安装但解析失败”“能解析但无文字”分开处理，不能全部模糊成未核验。 | 损坏文件无法缓存跳过；已核验的正常文件零下载复用；已安装解析器发现异常时明确报告，不能按正文成功统计。 |
| 高 | 首次连接超时，底层会话却已附加到扩展状态页；使用令牌后，连接返回成功，但目标是扩展 `connect.html` 页。程序会把内部页面误当成可用论文页。 | 连接成功前排除浏览器内部页和扩展页面；分别检查目标地址、页面脚本和绑定状态。明确选择普通标签，或由用户指定新建测试页，不能随意换到其他现有标签。 | 状态页、连接页不返回“网页已验证”；关闭连接页后仍能操作明确绑定的普通页。 |
| 高 | 临时连接页 URL 带有连接参数，现有连接缓存会原样保存。本轮已清理缓存中的临时参数，报告未包含令牌。 | 内部连接地址不进入正常会话元数据；日志和错误输出统一过滤令牌、临时连接参数。环境变量只交给运行进程。 | 连接成功、失败和超时三种输出均不含令牌；共享包仍排除所有会话状态。 |
| 高 | 文章页验证完成后，OneTrust Cookie 遮罩挡住 PDF 按钮，点击在 8 秒后超时。最终只提示“处理验证或保存 PDF”，没有指出遮罩。 | 在可见下载控件点击前识别可见 Cookie/同意弹窗，返回具体的 `needs_consent` 原因；用户已给出选择时执行对应按钮，否则询问。不要强制点击穿透遮罩，也不要自行接受全部可选 Cookie。 | 遮罩存在时不点击底层 PDF 按钮；关闭后再点击一次。提示写出当前弹窗及所需动作。 |
| 高 | Cookie 弹窗关闭后，PDF 按钮点击成功，但 PDF 地址另行出现 Cloudflare 验证。文章页通过验证不等于正文地址通过。 | 为文章页和正文请求分别记录状态；识别当前 HTML 验证页和真正的 PDF，保留当前篇并等待实际回复。 | 验证 HTML 不计作 PDF；不换来源、不换下一篇、不自动重试验证码。 |
| 高 | 用户回复“PDF 已打开”后，原命令续跑重新回到文章页，再次点击超时，没有事件或文件。它没有保留已经打开的 PDF 阶段。 | 检查点区分文章页、正文请求、PDF 已打开、待保存和已落盘。恢复时先核验文件，再读取绑定页面的实际地址、类型和来源；确认仍是同篇 PDF 时从保存阶段继续，不回文章页。 | 人工验证后保持同篇 PDF；文件已落盘时零点击恢复；没有文件时也不重复此前已经完成的跳转。 |
| 高 | Oxford 和首篇知网先后卡在“等待可见、启用且稳定”。知网恢复前读到 `hidden`，调用 `page.bringToFront()` 后变为 `visible`；原篇和第二篇均点击成功。 | 将明确绑定的任务标签前台准备纳入共用点击流程，核对实际可见状态后再点击；错误提示区分后台、遮罩和真实验证。继续做重复对照，不只增加统一超时。 | 本轮支持“前台准备可解决这次知网点击超时”，但不足以证明它是所有站点超时的唯一原因；Oxford 未重测，Windows 另验。 |
| 高 | 知网两篇均点击成功且文件落盘，但记录都是 `no_event`，弹出页地址未提供有效诊断；归档靠下载目录备用检测。 | 排查官方扩展对新开页、立即关闭页和下载事件的转发；保留“点击结果—事件—文件”的独立状态。继续使用唯一、稳定、作者匹配的文件检测，缺事件不能触发第二次点击。 | 分别报告事件捕获成功及目录恢复成功；新标签下载即使无事件也不会重复点击、误认别的文件或丢失当前篇。 |
| 高 | 扩展的“点击正文链接 → 下载事件 → 文件落盘”链路在此样本未通过。macOS 已验证的原生保存只接入 Apple Events 后端，不能算作扩展已具备相同能力。 | 先修复连接、遮罩与续跑，再单独验证“查看器已打开但无下载事件”。评估官方扩展可用的下载/查看器控制；若为 macOS 扩展增加原生保存，须可靠对应同一窗口和标签，并复用既有目录、覆盖与文件核验保护。Windows 另做实机验收。 | 独立报告下载事件、直接文件下载、原生保存和人工保存；只有真实落盘并核验才算该路径通过。 |

## 建议实施顺序

1. 先修复下载完整性与损坏文件缓存，消除“文件不合格却返回成功”。
2. 纳入已验证有效的前台准备，修正普通标签识别、连接缓存和敏感参数过滤。
3. 修正验证后的阶段恢复，使已经打开的 PDF 不被重开文章页替换；补齐 Cookie 遮罩提示。
4. 排查下载事件缺失，保留目录恢复；单独实现并验收扩展的 PDF 查看器保存策略。
5. 用本轮四篇与 Oxford 重做完整流程，再由 Windows 测试者验证。macOS 结果不替代 Windows、其他模型或 Harness 验收。

`doctor` 的“页面可读”与“下载可用”应分开呈现。此次知网的点击与文件恢复已通过，Oxford 扩展自动保存仍未通过。安装扩展、页面打开、找到链接、文件归档和正文核验，是不同阶段。

### 令牌与前台对照

用户回复“再试一次吧”后，按真实回复记录恢复决定。令牌只传入运行进程，沿用已有会话，没有再次调用 `browser connect`。只将已绑定的知网任务标签置前台，未切换到其他用户标签。前后状态记录在 `multi-site/foreground-preflight.json`。

因此，此次成功不能简单归因为“补上令牌”：此前同一会话已可操作网页；本次同时执行且直接观察到的变化，是绑定页面由 `hidden` 变成 `visible`。前台准备目前是测试时的临时操作，尚未写入下载源码。

### 出版社文件完整性诊断

为区分文件复制问题与接收阶段问题，另对同一公开 PDF 地址做只读 GET 诊断，不使用登录 cookies，也不将诊断响应计入交付。

| 来源 | 同一次 GET 声明的长度 | 实际接收 | 文件尾部 EOF | 结论 |
|---|---:|---:|---|---|
| DRPress | 1,380,917 字节 | 1,359,872 字节 | 无 | 少 21,045 字节；与两次 CLI 文件的 SHA-256 相同 |
| Frontiers | 1,271,612 字节 | 1,244,267 字节 | 无 | 少 27,345 字节；这次诊断比首次 CLI 文件又少 20 字节 |

这些证据确认接收不完整，并暴露了应用没有检查响应长度的缺陷；尚不能定位具体是服务端、缓存或网络链路在哪一段提前结束。DRPress 文件自身的线性化字典声明 7 页，但解析失败，不能因此汇报“7 页正文已核验”。

本轮没有做 Windows、其他 Agent/Harness 或独立扩展查看器的验收，也未修改运行代码，故没有重跑与此次文档变更无关的离线测试。历史测试数不作为此次真实下载成功的证据。
